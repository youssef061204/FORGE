# Sealed offline holdout protocol

This file contains the public evaluator handshake, with no individual mission requests or outcomes. Architecture authors may read this file and `schema.json` before their implementation freeze. They must not read the sealed JSONL files or the authoring script before that freeze.

Each line of `missions.sealed.jsonl` is an independent fixture case. Fields are `id`, `family`, `request`, `now`, `evidenceClass`, `resources`, `installedPrograms`, `conversation`, optional `lastToolId`, `missionInput`, `initialProgramState`, `schedulerTicks`, and `repeatEvent`. Resource descriptors match the public `FabricConnector` / `ConnectorDescriptor` contract. Descriptors always identify these as synthetic test fixtures, even while the runtime invokes a connector in its internally named `live` execution phase. No external request, credential, provider, Google account, Spotify session, AWS resource, or physical device is involved.

A resource contains a `descriptor`, mutable in-memory `collections`, and `handlers` keyed by the operation ID. Implement handlers generically:

- `constant`: return a clone of `value`.
- `list`: return `{ [resultKey]: clone(collections[collection]), ...constants }`.
- `artifact`: validate name/format/text, append an immutable local output to `collection`, and return its id/name/format/UTF-8 byte count. Reuse the real local WorkspaceConnector by seeding its public WorkspaceState when practical. The supplied document IDs and content hashes are fixed fixture data, not answers.
- `append`: append validated arguments with generated `idField` using `idPrefix`, and optional constants. Return explicit `result` if supplied, otherwise `{id}`.
- `update`: select exactly one row where `row[selector.field] === arguments[selector.argument]`, update only mappings `row[field] = arguments[fields[field]]`, and return `{id}`. An absent or nonunique target fails.

No handler may branch on case ID, request wording, expected route, desired output, or installed tool name. Validate operation arguments against the descriptor. Reads clone current fixture tables and are permitted in replay. Writes are prohibited during replay. In the runtime execution phase, writes affect fixture memory only. Deduplicate writes by the runtime-provided effect key. Retain write logs, execution receipts, baseline collections, and final state as evaluation evidence.

Installed-program entries contain public ProgramDrafts plus id/version/status/goal/description/grants/bindings/programState. Materialize a normal installed Program using the ordinary runtime validation path or a contract-valid store seed; compute hashes from the supplied source and actual fixture descriptor context. Do not replace installed source with newly generated code for reuse. Two choice-only context programs also carry no-op executable fixtures; their purpose is unresolved active-tool context.

For a fresh-inference run, providers receive only the request, public resource descriptions, authorized observations, ordinary installed-program metadata, and structured prior context through the product interface. Never include expected JSONL, authored recordings, evaluator postcondition expressions, or the authoring script in provider input. Use only a genuinely local cached model if available and explicitly label that inference evidence separately.

For the offline integration run, `recorded-solutions.sealed.jsonl` supplies independently authored fixture solutions through an injected test provider. These outputs were written during corpus authoring, not returned by a live provider or local model. This tests routing transport, grounding, compile, permissions, execution, postconditions, and persistence against recorded outputs. It does not establish fresh intent-understanding or generation accuracy. An output that fails must remain a failure; do not silently substitute oracle-derived source. Record later output revisions in separate files with their own timestamps and hashes.

Each mission begins with isolated state and the fixed `now`. Compile/replay/install through ProductRuntime. Authorize only permissions explicitly needed and exposed by the compiled tool; report them separately from any preseeded grants. Execute an initial event with `missionInput`. If `repeatEvent` is true, repeat the identical event ID and require zero extra committed writes. Reload the persisted state into a fresh runtime before supplied scheduler ticks. For each tick, apply only its `replace` collection mutations, advance the fixture clock to `at`, then dispatch through the actual scheduler or equivalent documented trigger-event entry point using `eventId`. Repeating a tick event must also cause zero extra writes. A missing scheduler path is a capability failure, not permission to manufacture a result.

`expected.sealed.jsonl` is evaluator-only. Match by ID after the result has been captured. It stores acceptable canonical routes, an exact permission set, generation policy, semantic postconditions, and side-effect bounds. Postconditions are generic data predicates: artifactEquals, collectionContains, collectionCount, collectionUnchanged, notificationContains, programPersisted, programStateContains, existingProgramsUsed, extensionLineage, connectionRequest, clarificationQuestion, unsupportedExplanation, noProgramCreated, and noWrites. `collectionContains` and `programStateContains` use recursive subset equality; arrays preserve order. `collectionUnchanged` compares complete before/after collection values. `artifactEquals` compares parsed JSON structurally, CSV parsed cells with normalized line endings, or exact text. Multiple equal filenames may correspond to different immutable outputs over time. Notifications must contain the specified text. Persistance requires a reload and the specified enabled trigger. Reuse preserves source/hash identity, while extension requires an actual parent lineage and the original installed tool preserved in history.

Clarification and connection checks must identify the materially missing choice or resource and must not claim completion. The legacy public route union lacks UNSUPPORTED. The corpus preserves canonical semantic disposition independently, notes that existing contract gap, and retains legacy transport in the authored recording. Do not silently count an unavailable canonical route as exact route accuracy. Report route accuracy and correct semantic refusal separately if the architecture cannot represent both yet.

Mission success requires all applicable postconditions and exact permission match. Merely executing a program, returning success, or producing a proposed operation is insufficient. A failed postcondition alongside a success claim contributes to false-success rate. Separate recording acceptance, route accuracy, execution status, postconditions, persistence, and permission metrics. Preserve failure evidence without editing the sealed case or expected result. Any evaluator correction must be a versioned erratum, retain the original, state its justification, and report both scores.

Before unsealing, the architecture owner records source commit/tree hash and an explicit freeze timestamp. Verify the manifest hashes. Then run the sealed set once and preserve complete results. Subsequent changes and reruns are developmental follow-ups, not a pristine first holdout attempt. No architecture source changes may contain benchmark-specific routing, identifiers, mission templates, or lookups into this directory.
