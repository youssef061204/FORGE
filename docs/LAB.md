## Protocol and access

Existing Streamable HTTP endpoint: /api/mcp, protocol 2025-11-25. Four additional fixed tools: forge.mission, forge.rehearse, forge.evidence and forge.briefing. Existing tools and installed capability discovery remain intact. Simulator rediscovery calls real tools/list; stateless listChanged=false remains truthful.

Owner actions use the authenticated, origin-checked /api/lab endpoint, not generated executable code or an approval MCP tool. Authentication uses the repository's existing owner API-token model. Voice approval is explicit confirmation in that session, **not biometric identification or a separate authentication factor**.

Lab state persists in the existing store. At most five experiments of 20 pairs and three private checkpoints are retained. Lab responses omit checkpoint snapshots and challenge hashes. An experiment may continue while the live City evolves: “unchanged” means the experiment never writes to the authoritative City. Only one experiment runs per server instance. Interrupted in-process jobs do not resume after restart. This is a single-instance prototype.

## Alexa+ track framing

The [official FAQ](https://amazonappdev2026.devpost.com/details/faqs) says preview SDK/toolkit/simulator access is limited to selected partners. The [competition rules](https://amazonappdev2026.devpost.com/rules) permit an independently hosted MCP server and custom Alexa-style web experience. FORGE follows that path; native Alexa+ integration is not verified.

For future native integration, the [Amazon MCP quickstart](https://www.developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-quickstart.html) specifies OAuth and remote HTTPS requirements. Native tool refresh is deployment-bound. Simulator rediscovery must not be presented as native Alexa refresh behavior.

## Reproduce

Run npm run verify:lab for genuine local-worker evidence through the official MCP SDK: ten additions at their applicable boundary, 60 experimental pairs, v1.1 source change, signed capsule import with zero grants, fresh local Futures, approval, execution, restoration and rollback. Uses an explicitly labeled development model double. Does not claim physical voice or Bedrock use.

Run npm run verify:city:aws separately for the real compiler's Bedrock request in ca-central-1 through profile forge, schema validation, independently generated source algorithms, Futures, exact approval and MCP invocation. AWS mode fails visibly and never substitutes fixture results.
