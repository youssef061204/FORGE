# FORGE: useful software, built locally

Decision date: October 21, 2026. User constraint: no paid features or billable services. This supersedes the prior paid-cloud acceptance plan.

## Audit and decision

1. **Today:** two compiler generations coexist. The deployed app still starts in City; the newer resource-driven Home exists in source but is offline without Bedrock. Strong sandbox, broker, versions, MCP and benchmark infrastructure are already present. The 31-stage October 10 local benchmark completed; the old documentation and deployed UI do not reflect that work.
2. **Unique strength:** new executable software becomes an installed, revocable assistant tool after tests and exact permission approval. The broker, rather than generated source, holds authority.
3. **Obstruction:** the default path provides no useful result without cloud generation; disconnected integrations and research pages obscure the payoff. Prior fixture demos can be mistaken for open-ended synthesis.
4. **Core:** resource schemas, actual source generation, typed compilation, sandbox, read-only replay, owner approval, receipts, persistence, versions and MCP discovery/invocation.
5. **Distractions:** preset household routines, a game-like starting screen, duplicate research navigation, dashboards of subsystem metrics and repeated architecture slogans.
6. **Remove from the main journey:** routine buttons, legacy workspace navigation and code/provider/hash details before an outcome. Keep historical routes as explicitly labeled compatibility/research facilities.
7. **Inspect:** Twin, ML/CV/RL, CUDA, formal checks, old capsules, raw source, traces and historical AWS proofs. Preserve evidence and its scope.
8. **Merge:** one Home request and file context, one Tools list, one Activity record and one Inspect entry. Connector setup belongs to connection details.
9. **Default experience:** describe a task, attach a small CSV/JSON/text file if needed, discover available operations, generate with a cached local Ollama model, see real checks and proposed changes, approve exact file-read/output authority, run and download the actual result. No keyword planner and no model pull or paid fallback.
10. **Demo:** an unseen transformation of an uploaded table; missing tool in MCP, generated source tested/replayed, exact approval, new tool appears and creates a downloadable file. Refresh and reuse it; edit naturally into a new version. Briefly inspect the broker/Twin evidence afterward.
11. **Twin:** secondary proving ground for operational software, pan/zoom/select, no avatar or WASD.
12. **ML:** supporting research evidence with baseline/current provenance; do not claim real-world prediction, significant RL superiority, current CUDA success or universal formal safety.
13. **Highest user payoff:** genuine local inference plus bounded document read/save operations. This creates a useful result without requiring credentials or a paid API. Existing Google configuration is preserved; the user declined reconnection, so no Google writes are part of this work.
14. **Highest evidence payoff:** frozen natural-language missions through the actual local model/compiler/broker, with independent expected results. Report model failures, repair attempts, time to approval/run and exact permissions; separate this from hand-authored recorded-source regression cases.
15. **Do not build:** another Lab, another ML model, paid cloud infrastructure, remote model fallback, Spotify, provider OAuth onboarding, autonomous optimization or inflated benchmark counts.
16. **Architecture:** Home/MCP → resource discovery and bounded context → loopback-only local model → schema/typed source checks → isolated execution and read-only replay → exact hash/binding approval → trusted connectors → persisted output and result receipt. Cached installed tools skip generation when an exact request fits. External network/cloud authority remains separate and disabled for this free path.
17. **Scope:** finish this single file-to-tool-to-result journey, persist/reuse/extend/revoke it, enforce free-only execution centrally, run regression/browser/build checks, deploy locally preserving the existing state volume, and publish current scoped evidence. Native Alexa+ and new live Bedrock/Google claims remain unverified.

## Gates

The first local pilot found repeated mismatches between model-chosen observation refs and generated code. The local compiler now separates operation planning from source generation. The second inference receives exact host-derived ModuleInput/ModuleOutput types and the proposed synthetic tests. Both requests stay on the same cached local model; the final complete source still passes the ordinary runtime admission checks. One bounded repair may repeat this compilation process. Usage counts both underlying inference requests, and incomplete token measurements are labeled.

- Default `FORGE_RUNTIME_MODE=fixture` stays intact for old reproducible facilities. Interactive local inference is selected separately and labeled LOCAL MODEL.
- Loopback model endpoint, installed local model verification, no cloud model tags, no automatic downloads, bounded prompt/output/time and no redirects. Run the isolated Ollama server with cloud features disabled.
- Generated software receives no credentials, raw network, filesystem path or unrestricted tool handle. Uploaded data stays in the local store and sandbox inputs.
- Test assertions must include operation arguments for new behavioral cases; model-authored tests are evidence, not a proof of intent.
- New live local-model benchmark results are only published after execution. Earlier Bedrock evidence stays historical. Zero paid requests.
