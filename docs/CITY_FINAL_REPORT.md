# Concrete City and Lab report

1. **Architecture:** the existing ForgeService now owns CityFoundry, TwinEnvironmentProvider, GoogleEnvironmentProvider and CityLab. The existing store, worker, broker, release validator, trust, registry and versions remain the authority path.
2. **Routes/components:** root and /city use ForgeCity and CityCanvas; /lab uses ForgeLab. Added /api/environment and /api/lab. ForgeApplication wraps root layout. Old /studio, /world, /live, /capabilities and Google routes remain.
3. **Rendering:** Canvas 2D with an authored pixel renderer, no Phaser dependency. One animation frame loop and refs interpolate authoritative positions without React state updates each frame. Resize, input and animation listeners clean up.
4. **Simulation:** pure City state transitions, persisted authoritative revision, one server tick actor, typed owner controls, dynamic weather/day-night, graph movement, damage, hazards and power allocation.
5. **Player:** WASD/arrows, sprint, nearby resource inspection, map, pause and keyboard inspector; building/river/boundary collision and typing isolation.
6. **Agents:** 52 civilian traffic vehicles, three responders that park until dispatched, 64 pedestrians with real path progress, evacuation and shelter reservations.
7. **Hazards:** flood, wildfire, earthquake, tornado, blackout, storm, gas and traffic; each updates simulation state rather than only an overlay.
8. **Randomness:** seeded LCG within each fork; cryptographically drawn paired seeds and separately paired exogenous weather/incident stream. Persisted seeds make comparisons inspectable.
9. **EnvironmentProvider:** observe/query/subscribe/execute plus resource, capability and constraint descriptions. Twin is authoritative; Google delegates the existing OAuth connector and per-write permission broker. No new mail/calendar dispatcher.
10. **GoalContract:** strict measurable constraints and weighted objectives plus supported typed actions. Exact permission derivation and host safety gates reject invented actuators and overbroad manifests.
11. **Free-form pipeline:** actual discovered resources/constraints/software and owner request enter Bedrock, which returns interpretation and source candidates. Fixture is explicitly a fixed development double, not general understanding.
12. **Executable synthesis:** one typed execute function using host-supplied ModuleInput/ModuleOutput; strict TypeScript compilation, restricted AST and schema-validated output. Repair cannot change the accepted contract.
13. **Candidates:** three emitted implementations, actual source hashes and normalized AST diversity checks. Extension compares the previous actual source as an additional candidate and baseline.
14. **Sandbox:** real isolated module worker, bounded VM/runtime/output, no imports or arbitrary host APIs; same three-node DSL execution and atomic broker. Real Docker checks cover both module and workflow paths.
15. **Futures:** private stores from one current snapshot; 20 paired runs per viable program plus baseline, 120 simulated seconds each, actual policy invocations every 40 seconds.
16. **Comparison:** reject any sampled hard violation/worker denial, then rank safe candidates by p95 normalized loss and mean. Mean/median/worst/failure counts and raw terminal metrics are exposed.
17. **Hard safety:** critical power floor, critical building protection, road-risk gates, contiguous safe routes, responder-only dispatch, bounded shelters/grid, exact digest/binding/grants and source/output schemas.
18. **Admission:** matching source, goal, report and 20 safe rollouts; exact owner digest approval. Lab optionally adds a 60-second one-use final-speech challenge. It is consent, not voice identity verification.
19. **Deployment effects:** the real source returns actions; city.apply validates and atomically commits to the current City. Real successful traces establish the origin of power, signal, shelter and routing changes. Admission never restores a evaluated fork.
20. **Versions:** fixture lifecycle proof records actual v1.0 -> v1.1 source change, four compared candidates, owner promotion, signed export, UNTRUSTED import, 20 fresh local Futures, approved imported execution and rollback.
21. **Unified UX:** persistent rail, header, token and voice composer; authored City, compact inspector tabs, current versus branch labels, old workspaces preserved. Lab adds mission memory, voice approval/narration, experiments, uncertainty, signed receipts, checkpoints and paired arena.
22. **Google regression:** existing OAuth/Calendar/replay/broker tests retained, including revision-aware consecutive changes. Existing main Google environment overlay remains configured. Authenticated live Google access/write remains unverified; no fixture result is labeled a Google write.
23. **MCP regression:** official SDK, Streamable HTTP 2025-11-25, stateless truthful rediscovery, retained fixed tools and dynamically installed tools. New Lab tools use the actual worker path. Native Alexa refresh is deployment-bound and is not claimed.
24. **Live Bedrock:** refreshed actual compiler proof uses profile forge, ca-central-1 and us.anthropic.claude-sonnet-4-5-20250929-v1:0. Request 0f2bb931-4b1a-4999-b354-2bd232071212 took 44,969ms; 28,346 input / 3,931 output tokens; schema validation and three 20-run candidates passed, followed by approval and successful MCP invocation. Historical proofs remain preserved separately.
25. **Verification:** current executed commands/results are in [VERIFICATION](VERIFICATION.md). Lab proof contains 60 actual experiment pairs, signature tamper rejection, nonce replay rejection, independent local import admission and current-world isolation. Browser tests substitute only physical speech APIs; they exercise real React, HTTP, compiler and broker behavior.
26. **Limits:** simulated infrastructure, bounded horizon/samples, no universal safety proof, one active City policy/server instance, restart-interrupted jobs, existing owner-token access model, browser-specific speech, no physical microphone/speaker verification, no native Alexa deployment or live Google-write claim. Optional AWS adapters are not counted as live services.
27. **Recording:** preserve the main state and Google overlay. Use an isolated fixture recording volume for a clean T0. Label fixture and live AWS explicitly; use recorded real AWS evidence or a prepared host AWS session. Do not expose private environment files, token fields or credential stores. Inspect source briefly outside the main take.
28. **Demo:** use the [175-second plan](DEMO.md): City goal, measured Futures, owner voice approval, actual new MCP tool, blocked attack, v1.1, paired arena, provenance, brief household/Google generality and honest live evidence.
