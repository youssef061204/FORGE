## Product decision

[NEXT_OVERHAUL.md](NEXT_OVERHAUL.md) chooses one primary journey: describe a task, attach bounded local data, discover resources, generate actual software with an installed local model, test and replay it, approve exact authority, run it and download the result. Home, Tools, Activity and Inspect are the product hierarchy. The Twin is a secondary software proving ground. Legacy routes remain labeled compatibility/research surfaces; their presence is not proof they belong in the main navigation.

Preserved: strict compilation, isolated execution, structured proposals, trusted broker, exact version/binding approval, revocation, persistent tools and outputs, receipts, MCP, historical research and failure evidence. Rejected: preset household routines as the normal interaction, a City game as the landing page, more model/Lab surfaces, paid fallback, Spotify and new OAuth onboarding.

The owner declined Google reconnection. Existing private configuration is preserved; no Google write or reconnection is part of this work. Native Alexa+ remains unverified. Historical AWS artifacts remain historical.

## Implemented and verified

- `src/forge/product/workspace.ts` supplies bounded CSV/JSON/text reads and `workspace.save`. The trusted primitive parses and stores data; generated source implements the requested transformation. Saved output has a real local receipt and download path.
- `src/forge/product/local-model.ts` uses an installed GGUF model through the local Ollama service. It rejects remote/cloud model identifiers, verifies installation, bounds responses/time, refuses redirects and has no automatic model download or hosted fallback. Docker-to-host access is explicitly allowed through `host.docker.internal`; this is a local host bridge, not an arbitrary remote endpoint.
- The provider separates operation planning from source generation against host-derived types. Both stages use the cached local model. One bounded repair is allowed, and underlying inference requests are all counted. The corrected provider uses host-assigned read references and typed observation grammar. Its actual browser lifecycle and packaged restart passed; its complete 18-case corpus finished with seven passes, nine failures and two blocked dependencies.
- Runtime tests now require concrete operation arguments and compare actual saved JSON/CSV/text content for new behavioral cases. Model-written tests remain fallible; benchmark output must match an independently specified oracle.
- Workspace input names cannot silently identify two different uploaded contents. The duplicate-name guard and format/permission/receipt regressions passed 13 focused tests; this does not replace a final complete suite.
- `src/forge/cost-policy.ts` centralizes default-deny policy for billable/cloud paths, with checks before construction and SDK dispatch. External OpenAPI/MCP network transport is also blocked in free-only mode. Injected SDK/HTTP tests do not establish a live connection.
- Home displays files, proposed results, tests and requested access; Tools and Activity expose persistent software and receipt-backed results. Source, hashes and research move to Inspect. Final browser, build, deployment, process restart and desktop/mobile visual checks passed with evidence below.
