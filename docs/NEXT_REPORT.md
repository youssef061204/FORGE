## 1. Diagnosis

FORGE's strongest work was hidden behind a fragmented, simulation-first interface. Preset routines and fixture language made a software compiler feel like a menu of demos. The product direction is now concrete: request a useful result, let FORGE build the missing bounded tool over available resources, inspect what it proposes, approve its exact access and receive the actual output. Broad reliability is not established: both the initial and revised local development runs exposed type, observation-reference, source and output-contract failures.

## 2. Major decisions

Kept the broker, sandbox, typed source generation, replay, exact approval, persistent software, versions, revocation, MCP and retained failures. Redesigned the main hierarchy as Home, Tools, Activity and Inspect. Moved the Twin and research beneath inspection; kept historical routes as labeled compatibility facilities. Removed household routine presets from the main journey. Rejected another Lab, another ML model, game controls, paid inference/cloud infrastructure, Spotify and OAuth onboarding. [Decision record](NEXT_OVERHAUL.md).

## 3. User experience

The default flow is: upload a small CSV/JSON/text file, describe an outcome, see a proposed tool and real check results, review the exact file-read/output access, approve, run and download the saved file. Tools retain programs; Activity shows effects and failures; Inspect exposes source and technical evidence. The [real local-model browser proof](../artifacts/local-synthesis/browser-proof.json) passed this journey and its natural extension/revocation steps. The [packaged main-instance proof](../artifacts/local-synthesis/production-proof.json) also generated and ran an actual tool; a [real process restart](../artifacts/local-synthesis/production-restart-proof.json) retained its authority, output and invocation. This puts the requested result ahead of provider metadata and architecture.

## 4. Core FORGE loop

The runtime discovers typed resource operations and retrieves installed tools. Exact matching approved goals may reuse existing software without inference. Other requests go to the installed local model, which can select synthesis, extension, composition, clarification or a missing connection. The current compiler revision separates operation/test planning from source generation against exact host-derived TypeScript interfaces. Source passes strict compilation, sandbox tests and read-only replay before installation. One bounded repair is allowed; both stages and repair calls count toward usage. Failed generation surfaces as failure and never silently becomes a fixture result. The initial frozen corpus demonstrates that route/schema validity alone does not establish mission success.

## 5. Real-world payoff

The new useful primitive is a real local document result, requiring no paid API or external credentials. In the [current real-browser proof](../artifacts/local-synthesis/browser-proof.json), locally generated software read `orders.csv` and produced the downloaded `totals.json`: Notebook 20, Pen 12, Lamp 75. A natural edit generated v1.1.0 with `grandTotal: 107`, requiring fresh approval. Both results matched independent test expectations. The program requested one exact file-read permission plus `workspace.outputs.write`. Earlier [Notebook 15 / Pen 20 / Lamp 50 evidence](../artifacts/local-synthesis/semantic-effects-2026-10-22T22-20-44-043Z/proof.json) remains preserved as a separate pre-correction mission. These successful examples do not establish arbitrary file-task reliability.

## 7. Generated software

The model generates a complete bounded `execute(input: ModuleInput): ModuleOutput` function containing actual transformation/comparison logic, not a call to a scenario-specific host helper. The host controls operation schemas, input observations, allowed actions and permission derivation. Programs propose structured operations; only the trusted connector/broker may execute effects. Program source, tests, version, bindings, hashes, grants and run history persist through the state store. The browser proof verifies v1.1.0 with a parent hash, unchanged necessary permissions and empty grants before approval. The [production restart proof](../artifacts/local-synthesis/production-restart-proof.json) verifies the same installed hash, successful SDK invocation, real downloaded output and duplicate-event suppression after the container's [PID/start time changed](../artifacts/next-process-restart.json). No fresh generation was needed after restart.

## 8. Trust

Generated code receives no raw network, filesystem path, credentials or unrestricted connector handle. Strict typing, isolated workers, bounded inputs/outputs, schema validation, permission/binding/hash checks and explicit owner approval guard execution. Replay intercepts writes. The [October 23 fixture trust suite](../artifacts/trust-evaluation.json) passed 12/12 categories, including signed capsule integrity, import trust reset, MCP and authority-revoking rollback. Model-authored tests are fallible; independent output oracles are necessary. Twin Futures and bounded Z3 checks remain supporting evidence, not a proof of arbitrary source or physical safety.

## 9. Twin

The Twin is a secondary proving ground for operational software. Generated programs propose typed actions, paired stochastic Futures compare candidates, and the trusted host applies constraints before approved simulated effects. Pan, zoom and selection support inspection; avatar/WASD gameplay is outside the direction. Real imported map geometry and real external datasets remain clearly separate from simulated control. There is no claim of control over actual roads, hospitals, power or emergency systems.

## 11. New technical work

Substantive additions are the local Ollama provider, bounded Workspace primitives and receipt-backed downloads, exact file-derived permissions, shared default-deny cost enforcement, behavioral assertions over operation arguments, and a frozen natural-language file-mission corpus with independent expected output. Behavioral assertions compare actual saved JSON/CSV/text content, rather than merely counting save operations. Host-assigned read references and typed observation grammar align planning fixtures with the generated source interface. Explicit edit context supports a new version of an installed tool. The corrected compiler passed the real browser lifecycle and packaged restart, but completed only 7/18 benchmark missions. UI consolidation makes the existing generated-program system usable without exposing every subsystem first.
